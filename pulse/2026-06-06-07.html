Wall Street Copies Crypto's Political Machine

FinTech Collective

FinTech Collective's lead essay is the cleanest read on financial lobbying right now: after years of keeping quiet post-crisis, the biggest banks watched Fairshake turn crypto into a disciplined single-issue political force and decided to copy the model. The eight largest US banks have reportedly created American Growth Alliance and moved about $100 million into left- and right-leaning nonprofits since December.

The useful signal for Hiro is that stablecoin yield, tokenized deposits, and bank/crypto boundary fights are no longer narrow product debates. They are becoming durable political infrastructure contests, which means product strategy in consumer finance increasingly has to model regulation as a competitive surface, not an externality.

My take: the banks are learning from crypto because crypto proved that narrative plus committee access can move markets. That is awkward for incumbents, but rational.

"Wall Street has decided the responsible move is to behave exactly like the upstarts it spent years lecturing."

Why it matters: Directly relevant to Hiro: stablecoin savings and bank-regulated yield are moving from product design into political market structure.

Simon Willison Builds a Python Sandbox with MicroPython and WASM

Simon Willison's Newsletter

Simon released micropython-wasm, an alpha package that runs Python code inside a WebAssembly sandbox via wasmtime. The design target is practical: PyPI-installable dependencies, memory and CPU limits, controlled file/network access, persistent interpreter state, and selectively exposed host functions.

The interesting part is not just the implementation; it is the product shape. As agent products start executing user- or model-generated code, the sandbox becomes a core trust primitive. Simon's approach uses MicroPython in WASM, request queues for persistent sessions, and host functions as the narrow bridge back into the app.

My take: this is exactly the kind of boring infrastructure that makes agentic software usable. The frontier model is less important than whether the runtime can fail closed.

"I’d love to be able to run plugin-style code in an environment where it is unable to read unapproved files."

Why it matters: Hiro will need constrained tool execution and private-data protection. This is a concrete architecture pattern worth tracking.

Agent Benchmarks Move Toward Long-Horizon Economic Work

AINews

AINews highlights a shift from short coding tasks to agent evaluations that look more like real work: Agents' Last Exam maps 1,000+ economically valuable tasks to occupational taxonomy, SWE-Marathon tests billion-token coding projects, and Meta-Agent Challenge tests self-improvement under sandboxed eval constraints.

The caution is equally important: reliability work from Princeton still finds frontier models are not meaningfully more dependable than previous models, and benchmark scaffolds themselves can leak answers or invite reward hacking. The meta-lesson is that agent progress is becoming an eval-design problem as much as a model-capability problem.

My take: for financial advice, this argues for production evals tied to actual user outcomes, not just tool-call success. The benchmark that matters is whether the advisor makes good, auditable decisions under messy constraints.

"Reality: the final eval."

Why it matters: A useful frame for Hiro evaluation: long-horizon, economically meaningful tasks with reliability and auditability measured directly.
